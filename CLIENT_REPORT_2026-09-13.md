# Отчёт клиенту — 13.09.2026

Готов очередной блок доработок по PRIME Electronics.

## 1. Дата и отложенная публикация статей

Добавлена возможность вручную указывать дату и время публикации статьи, включая прошлые и будущие даты.

Для будущей даты статья автоматически становится доступной в указанное время. В админке время указывается по МСК (UTC+3).

Также дата публикации теперь корректно используется на странице статьи и в SEO-разметке.

## 2. Авторы статей

Сделан полноценный раздел авторов.

Для каждого автора можно указать:
- имя;
- фотографию/аватар;
- краткую информацию об авторе.

В статье выбирается нужный автор, а его данные выводятся на сайте в блоке статьи.

## 3. Товарные блоки в статьях

Добавлена возможность привязывать товары к статьям.

Товарные блоки можно:
- выводить отдельной плиткой после статьи;
- вставлять в нужное место текста статьи через шорткод.

Для каждого блока в админке формируется шорткод вида:

```text
[[product-block:1]]
```

Цена, изображение и наличие товара берутся из актуальных данных каталога, поэтому их не нужно дублировать в самой статье.

## 4. Уникализация описаний товаров через ИИ

Реализована генерация описаний через GEN API.

В админке можно указать API-ключ и модель, после чего доступны два сценария работы.

### Для отдельного товара

В карточке редактирования товара рядом с полем «Описание» есть кнопка генерации.

После генерации:
1. показывается новый AI-вариант;
2. его можно вставить в обычное поле описания;
3. при необходимости текст можно вручную отредактировать;
4. окончательное изменение сохраняется штатной кнопкой «Сохранить».

Текущий текст товара автоматически не заменяется без подтверждения.

### Массовая генерация

В отдельном разделе админки можно запустить генерацию описаний для каталога и видеть прогресс обработки.

Для каждого товара сохраняется AI-черновик. После проверки можно:
- применить описание у конкретного товара;
- перегенерировать отдельный вариант;
- применить все готовые варианты массово.

При генерации используются существующие данные товара:
- название;
- бренд;
- категория;
- характеристики;
- текущее описание.

ИИ отдельно ограничен правилом не придумывать отсутствующие характеристики и другие факты.

Ориентир результата — естественный русский текст из двух абзацев объёмом около 500–1000 символов.

## На обсуждение: PE-04 — хлебные крошки категорий

По примеру из ТЗ для товара PlayStation 5 Slim в карточке товара хлебные крошки отображаются как полная цепочка:

```text
Главная → Каталог → Sony → Приставки → PlayStation 5 Slim → Товар
```

При переходе на саму категорию `PlayStation 5 Slim` клиент ожидает сохранить эту же иерархию без товара:

```text
Главная → Каталог → Sony → Приставки → PlayStation 5 Slim
```

При проверке админки выяснилось, что категория `PlayStation 5 Slim` сейчас сохранена как корневая — в поле «Родительская категория» указано «Без родительской категории».

Из-за этого страница категории может построить только цепочку:

```text
Главная → Каталог → PlayStation 5 Slim
```

При этом карточка товара использует дополнительный контекст категорий товара и поэтому может показывать более полную цепочку.

Перед внесением программных изменений нужно согласовать с клиентом, какая структура категорий является правильной. Если `PlayStation 5 Slim` действительно должна находиться внутри `Sony → Приставки`, корректнее исправить родительские связи категорий в данных, а не добавлять отдельную логику, которая будет угадывать иерархию по товарам или предыдущему переходу.

**Вопрос клиенту на встречу:** нужно ли привести дерево категорий к ожидаемой структуре (`Sony → Приставки → PlayStation 5 Slim`) и по этому же принципу проверить остальные категории?
