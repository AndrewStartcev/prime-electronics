# PE-05 — визуальный конструктор статических страниц

Дата реализации: 15.09.2026.
Статус: код готов к локальной проверке, `TASKS.md` пока не переводится в DONE до пользовательской проверки.

## Архитектура

Вместо одного HTML-поля реализован ACF Flexible Content-подобный конструктор.

SEO и идентичность страницы по-прежнему хранятся в `StaticPageSeo`.
Контент конструктора хранится отдельно в `StaticPageContent`:

- `path` — URL страницы;
- `blocks` — упорядоченный JSON-массив блоков;
- `createdAt` / `updatedAt`.

Так существующая SEO-модель не ломается и остается совместимой с уже внедренными SEO-настройками.

## Доступные блоки

1. `hero` — H1/шапка и подзаголовок.
2. `richText` — заголовок + HTML-текст.
3. `imageText` — текст и изображение в две колонки.
4. `cards` — карточки преимуществ, условий, контактов.
5. `stats` — крупные показатели/цифры.
6. `steps` — последовательность шагов.
7. `table` — таблица.
8. `info` — информационный/предупреждающий блок.
9. `cta` — CTA с кнопкой.
10. `map` — карта.
11. `contactForm` — стандартная форма обратной связи.
12. `promotionGrid` — динамическая плитка текущих акций.
13. `productGrid` — динамическая плитка актуальных товаров.

Каждый блок содержит `type`, `version` и `data`. Backend принимает только зарегистрированные типы блоков.

## Админка

Добавлена страница `/pages`:

- список страниц;
- создание новой страницы;
- URL и название;
- SEO H1 / Title / Description;
- включение/выключение страницы;
- добавление готовых блоков;
- редактирование данных блока;
- изменение порядка блоков;
- удаление блоков;
- удаление/отключение страницы;
- ссылка на локальный просмотр.

Из раздела `/seo` добавлена кнопка «Конструктор страниц».

## Storefront

Для уже существующих маршрутов:

- `/about`
- `/delivery`
- `/warranty`
- `/contacts`
- `/promotions`
- `/trade-in`
- `/privacy`
- `/cookies`

используется server-side rewrite через Next.js `proxy.ts` на внутренний managed route. Поэтому содержимое конструктора попадает в HTML уже на сервере, а не подменяется после гидрации браузера. Старые `page.tsx` остаются в репозитории как контрольная точка и источник исходного дизайна, но запросы к этим восьми URL обслуживаются managed renderer после применения миграций.

## Начальное наполнение

Миграция `20260915210000_static_page_builder` создает `StaticPageContent` и сразу заполняет шесть основных текущих страниц блоками на основе существующего содержимого.

Миграция `20260915211000_static_page_builder_seed_seo` добавляет читаемые названия этих страниц в `StaticPageSeo`, только если записи для этих путей еще отсутствуют. Существующие SEO-настройки не перезаписываются.

Миграция `20260915214000_static_page_builder_legal_pages` добавляет в конструктор существующие юридические страницы `/privacy` и `/cookies`, сохраняя их текущий текст и не перезаписывая уже существующие/отредактированные записи.

Динамические данные не фиксируются snapshot-ом:

- блок акций берет текущие `promotionsData`;
- блок товаров запрашивает актуальный каталог.

## Prisma

Модель `StaticPageContent` находится в основном `prisma/schema.prisma`. `prisma/prisma.config.ts` явно указывает на этот файл, чтобы Prisma Client 7.4.2 стабильно генерировал delegate `prisma.staticPageContent`. Миграции остаются в `prisma/migrations`.

## Что проверить локально

1. `prisma validate`.
2. `prisma migrate status` / применение новых миграций.
3. Backend build.
4. Admin build.
5. Storefront build.
6. `/pages`: все 8 управляемых страниц присутствуют и уже содержат блоки.
7. Изменение текста блока сохраняется и отображается на storefront.
8. Изменение порядка блоков меняет порядок на storefront.
9. `/privacy` и `/cookies` открываются через managed renderer и содержат исходный текст.
10. Отключенная страница возвращает недоступный/404 сценарий вместо старого содержимого.
11. Существующие SEO Title/Description/H1 не теряются.
